## 一、总体评价

推理层与源码语义贴合度**远超预期**：墙反馈（树篱=空/关门=墙）、8 方位声响方向、亚空间两步、心跳掩盖、陷阱奇偶、按钮门时序（异或方程组）、封闭传送门初始化判定、出生 BFS 回退、特殊事件变体等关键语义全部正确；"保守不冒充完备"的哲学贯彻一致。

但两轮审查一致指向同一个结构性结论：**问题几乎全部集中在输入解析层——源码产生的 30 余类信息中，工具只接住了约 18 类**。大量本可利用的强约束（屏蔽器方位、热浪范围、金币拾取、同格声响、BOSS 声响方向、门变化计数）被静默丢弃，少数还会错绑。下面按"错误性 → 遗漏性 → 功能机会 → 工程"四级展开。

## 二、A 级：会产生错误结论或错误归属的问题

### A1. 公屏"停止信息=公开"墙壁错绑 + 邦邦 BOSS 公屏墙误归属

源码 `停止信息=PUBLIC` 时超时/主动停止的四墙**附加在公屏**（`玩家 2号 超时未行动…【第 3 回合】您所在位置的四周墙壁信息…墙空空墙`）；邦邦 BOSS 每回合公屏炸弹四墙（`邦邦所在位置的四周墙壁信息…`）。工具的墙壁 player 推导依赖文本中最后的 `[N号]` 标记，两者皆 `null` → **归给粘贴时的接收视角**。已实测复现：0 号视角粘贴 2 号的超时墙 → 挂到 0 号第 3 回合 pending → 0 号贴轨迹后**错绑到 0 号终点**。  
**建议**：识别"超时/挂机/邦邦/BOSS"上下文 → 显式排除或弹归属询问；`player:null` 带回合号的墙与当前视角已有墙冲突时警告而非静默拼接。

### A2. 心跳掩盖的**沙沙**私信不解析（正则漏源码原文）

源码两种掩盖私信（mygame.cc L1295）：啪嗒版 `移动发出【啪嗒声】…掩盖…`（工具可解析 ✅）；**沙沙版 `移动进入【树丛】，声响被巨大的心跳声掩盖…`（无"沙沙声"字样，实测 0 条识别 ❌）**。心脏局里最有价值的一类心跳私信全部失效。  
**建议**：正则补 `【树丛】/【浆果丛】` 分支。极小改动。

### A3. 同格声源私信完全不解析

源码同格时发送文学化 hint 文本（"你听见有人进入了你所在的树丛……"/"同一片液体里溅起了另一阵啪嗒声……"）。**点杀（默认开启）下同格文本总是发送**，非点杀时声源非目标也发送——实战常见。实测 soundPattern 匹配 0 条。丢失"声源与听者距离=0"的强约束（`bearings`/`locate` 管线已支持同格，**只差输入端**）。  
**建议**：`[N号(第M步)]` 标头 + 宽松关键词（`进入了你所在`、`一臂之遥`、`同一片液体`）→ `direction:'同格'`。hint 文案有多个随机版本，建议按标头+特征短语匹配，未识别继续留作笔记。

### A4. 隐匿（回合/单步）真实输出格式均失效

- **回合隐匿** `<隐匿行动>`：被 `clean()` 的 `/<[^>]*>/g` 当 HTML **剥成空串**（实测 `M.clean('<隐匿行动>')===''`）→ 轨迹空。
- **单步隐匿** `U+FFFD`（源码 Hide_ 的 `NewContentRecord("")`）：tokenPattern 忽略 → **该步被静默吞掉**。实测 `→\uFFFD↑` 读成 2 步——实际 3 步，**后续轨迹系统性错位一格**。
- 现有测试用 `(隐匿)`/`[↑未知]`——**这两个格式在当前源码中不存在**，属过时假设。    
  **建议**：clean 前捕获 `<隐匿行动>` 转 marker；`U+FFFD` 解析为 `{outcome:'unknown'}` 位移（`locate()` 已支持）；回归测试改用真实格式。

### A5.（新）粘贴"他人私聊赛况"时，本人轨迹的方向标注被静默丢弃

私聊完整赛况是按查询者定制的：**别人的轨迹带 `(方向)` 标注**。若用户把 2 号收到的私聊赛况粘到 0 号视角（未切换 view），0 号轨迹上的 `(左上)` 实为 2 号听到的方向，但工具把它当成 0 号听到的（`a=b=0`），随后在 build 中被 `h.a===h.b` 过滤——**方向信息静默消失，无任何警告**（实测复现）。  
**建议**：`a===b` 丢弃前发 warning（"这条方向标注的接收者与当前视角不符，请确认粘贴前点击了正确的玩家地图"）；或在识别到"含方向标注的本人轨迹+其他玩家轨迹同段"时提示切换视角。

## 四、S 级：强功能建议（基于源码结构的新发现）

### S1.（★ 最高价值）屏蔽器/小太阳方位 → 区块级强定位

核对全部 71 区块后确认：**JAMMERBOX 只存在于 44 号（普通）与 E13（逃生），且屏蔽器格都恰好是区块正中心 (1,1)；小太阳 43 号也只有一个、同样在中心格**。

这意味着：

- 收到 N6 心跳屏蔽器提示 或 声响"方向被屏蔽"私信（工具已解析后者但未利用）→ **"我的位置在某个 44/E13 区块的中心格周围 3×3 内"**。若区块池只有 44（无 E13），等于"我在 44 号区块的 9 格中的某格"→ 直接锁定区块种类！
- 热浪提示（5×5）→ 我在 43 号区块中心 5×5 内 ≈ 43 号区块 ± 1 格 → 锁定 43 号。
- 多人同时被屏蔽 → 多个"距屏蔽器 ≤1 格"约束交叉 → **屏蔽器绝对位置可唯一定位**，成为整张地图的锚点，再经平移传播到所有视角。

这是目前工具完全没有的一类约束（attach 级定位），且源码保证结构唯一，实现成本可控：在 matchBlocks 的 observations 里增加 `nearJammer`/`nearHeat` 观测类型即可挂入现有候选筛选。

### S2. 金币拾取 → 区块种类收窄 + 格级观测

COIN 只在 **45/46（提款机，金币在中心格、对角双传送门）与 49（花园宝藏，上下金币+中央陷阱）**。金币拾取是静默的（本人也不知道），但回合结束公示（N4）给出"谁拾了几枚"。于是：

- 某玩家公示获得金币 → 其当回合轨迹中存在踩中 COIN 格的步 → 该步落点区块 ∈ {45,46,49} → **整图候选立即收窄**；
- 49 的金币格与陷阱同列，45/46 的金币格与传送门同块 → 结合该步是否啪嗒/后续是否亚空间，可进一步区分；
- 拾取后 COIN 格变 EMPTY（可重复拾取计数可对账）。

工具完全没接金币系统。建议解析公示（N4）+ 标题徽章（N1），生成 `coinPickup` 观测加入 matchBlocks。

### S3. BOSS 声响三角定位（虚拟声源）

米诺陶斯每回合移动后巨响 `to_all`：**每个在场玩家都收到方向**（含被屏蔽变体）。工具的 pair 对齐/三角约束管线完全可以复用——把 BOSS 当作一个"位置未知的额外节点"：

- 多个听者同一回合的方向 → 交叉定位 BOSS 当回合位置（即使只收缩到若干候选）；
- 邦邦的公屏炸弹四墙 + "BOSS 在该格"→ 直接成为**地图绝对锚点**（墙观测+位置双证据）；
- 米诺陶斯"步数递增"规律可反推回合数，喘息（8 格内）约束 BOSS-玩家距离。

BOSS 局目前工具等于盲打，这是唯一的破局信息源。

### S4. 门变化计数接入异或方程组

timeline.js 已经把"未知按钮按了几次"建成 GF(2) 变量。公屏 N3 提示给出**本回合按钮触发总次数**：对只有一个按钮的区块，N 直接定该变量；多按钮时是和约束。把 N3 解析成 `pressesCount` 观测喂给 `Timeline.check`，按钮局的门状态推断会从"多数 unknown"跃升为"多数可解"。

### S5. 私信完整性反向校验（完整赛况+私信拆分的核心价值）

源码保证：**非首响 + 听者未被屏蔽 + 双方在局 ⇒ 方向私信必达**。因此工具可以做"漏贴检测"：

- 公屏轨迹中他人每个非首响声响步，对照各视角已录入的 hear 记录；
- 缺失 → 不是"无声证据"（README 明确不用负证据），而是**提示用户"你可能漏贴了 X 号第 N 步对你的方向私信"**；
- 已确认首响/屏蔽/隐匿的步自动豁免。

实测：`[1号]轨迹含[→沙沙]` 且无任何 hear 时，工具 0 警告。这个校验能把"完整赛况+私信"拆分流程从"靠用户自觉"变成"工具兜底"，是低成本高感知的功能。

### S6. "赛况粘贴向导"模式（完整赛况+私信拆分的 UX 升级）

当前流程要求用户理解"视角切换/接收者/公屏 vs 私聊"等概念（A5 的错向丢弃正是这个复杂度的代价）。建议增加一个显式的**导入向导**：

1. 检测粘贴文本类型（公屏赛况 / 私聊赛况 / 单条墙壁私信 / 单条声响私信 / BOSS 播报），给出识别卡片让用户确认；
2. 私聊赛况自动询问"这是谁收到的？"（默认=当前视角，可一键改）——从根上消灭 A5；
3. 公屏播报中的墙（超时/邦邦）自动识别归属或标记"未知来源"，不进任何视角；
4. 识别 N1 标题行自动更新玩家状态面板（在局/出局/逃生/金币数）；
5. 每次导入后输出"本次新增约束摘要"（新增墙 X 条、声响 Y 条、状态变化 Z 项、未识别行 W 行），配合 S5 完整性校验，让用户对"贴全了没有"有数。

### S7. 推理可视化增强

- **pair 证据矩阵**：多候选平移时，展示每个候选被哪些观测支持/排除/未检——现在只有一个候选数；
- **假设分支树**：hypotheses 的 ground/portal 分支及各自 rejections 已有数据，图形化后用户能看懂"为什么还没确定"；
- **回合时间轴回放**：lifecycle + roundEnds 已有全部数据，做"第 N 回合时各玩家在哪"的回放条，捕捉/逃生事件打点；
- **置信度分层着色**：把"观测事实 / 候选一致推断 / 唯一验证 / 未知"四层在图例中更显式区分。

### S8. 心跳推理增强（B4 的完整版）

利用"心跳步不参与合并"+"陷阱/热源强停步额外 +1 但无移动"两条源码事实：

- ×N 合并段内全部步排除心跳可能；
- 散步（非合并）第 1/4/7…步保留可能（现状）；
- 强停回合末步非心跳；
- 说明：HTML 版赛况的心跳步有 `<b>` 加粗标记可精确识别，纯文字版无差别——若用户粘贴时保留 HTML（工具 clean 会剥标签），可在 clean 前先提取加粗箭头标记，心跳步从"可能"变"确定"。

### S9.（远期）对局录像重放与赛后复盘

终局时机器人公开完整地图+初始地图（GetFinalBoard）。支持"导入终局地图 → 与本局推理对比 → 差异归因（哪条线索本可推出）"可做成复盘模式，也是验证工具正确性的最好回归集（真实数据自动积累）。

## 七、第三轮：决策支持层（D 系列）

**前提假设**：前两轮全部建议（A1–A5、B/N 系列解析、S1–S9 强功能、性能 P0）已落地。此时工具已经"知道一切能知道的"——但仍然只是一个**记录与推理面板**。第三轮的问题只有一个：**玩家看着这张图，本回合到底该怎么走？** 以下建议全部基于"数据已在现有/前两轮管线中"的验证结论，按落地难度分层。

### 7.0 顺带发现的一个新问题：声响粘贴顺序影响 sources 面板

实测复现：**先贴轨迹、后贴声响私信**时，方向约束在 `relations` 中正常生效（pair 对齐不受影响），但接收者视角的 `sounds` 流里没有 hear 事件 → **"其他玩家声源"面板（sources）显示不出来**。根因是 `buildOne` 的 `sourcePending` 是流式的，不会回溯到已处理完的轨迹。README 建议按顺序粘贴，但顺序鲁棒性本应是工具的责任（第一轮的 prepare() 已经做了全局 hears 预关联，只是没覆盖这条路径）。修复成本低，建议随 A 级一起处理。

### 7.1 零成本层：从"已知事实"直接推出"本回合提示"（纯 advice.js 文案增强）

**D20（★ 推荐首先做）心跳步 = 零暴露安全窗口**  
源码事实：心脏局中我的第 1/4/7/10/13/16/19 步必发全图无方向心跳，**完全掩盖同步地形声**——对手和听者收不到任何方向。也就是说：**心跳步穿越草丛/水洼/传送门零信息暴露**。工具已知 `heartPresence` 和我的步数，可在回合开始前提示："本回合你的第 4 步是心跳步，计划路线时把必经的声响地形安排在这一步。"同理反向提示对手："1 号本回合第 7 步是心跳步，若他届时穿越声响地形你不会收到方向。"

**D7 陷阱/热源状态台账**

- 陷阱有奇偶状态（奇进发声放行、偶进无声强停），**同一玩家第二次踩同一格陷阱必停**。工具已解析 `(陷阱)` marker，但只画地形不记状态。应跟踪"哪些陷阱格已被踩过几次"（公屏可观测），提示"再进 X 格必停步"（advice.js 已有半句提示，缺的是台账与跨回合状态）。
- 热源：**整局第二次进入热源强制停止**（且第一次进入后源码会私信警告"下一次进入将强制停止"）。工具应在我在过热源后，把所有候选热源格标为"禁入（会强停）"。

**D19 模式感知提示**

- 谋定后动（每回合 1 步）：路线规划退化为单步选择，建议直接给"信息增益最大的一步"；
- 大乱斗：逃生舱=随机传送，"逃生"不再终局 → 逃生价值评估逻辑切换；
- 炸弹人：拆弹条件（进入后停止）、引炸条件（进入后离开）提示，配合 N9 拆弹私信标记已知炸弹格。

### 7.2 低成本层：复用现有数据结构即可计算的决策视图

**D2 逃生路线规划（spawnCheck 的推广）**  
`spawnCheck` 已实现"在 witness 地图上按通行规则 BFS"。把它从出生检查推广为：对每个候选布局（或验证过的 witness）计算 **当前位置 → 各候选逃生舱的最短安全路径**，输出"距最近确认逃生舱 N 步（经 …），但若 X 号区块是 E2 则还有 M 步的路线"。多 witness 时给出路线的候选分布（"3 个见证中 2 个支持走右侧"）。注意必须沿用源码通行语义（热源/心脏/箱子/关门阻断，树篱需冲刺，传送门按 2 步亚空间折算）——这些工具全都有。

**D4/D18 "对手眼中的我"反向定位（信息不对称审计）**  
实测确认数据已在：`relations` 中每条 `a=对手,b=我` 的方向约束 + 我的公开轨迹，足以在每个对手视角的坐标系里运行 `locate()` 反推 **"1 号现在把我定位到哪几个格"**。再叠加 D18 时序版：回放我每个发声步"谁听到了、把他的定位收缩到了哪"。这两项把工具从"我知道什么"升级为"对手知道我什么"——追逃博弈的核心信息。  
（依赖 7.0 的顺序修复才能在面板稳定展示。）


**D17 对手知识面板**  
`views[X]` 本来就是每个对手的完整推理模型。聚合展示：每个对手对每个玩家的 locate 候选数、已确定的区块数、已验证墙数——一张"谁最危险（信息最多）"排行榜。纯 UI 工作。

**D16 潜行指数 / 声响暴露预算**  
计划路线时，逐格查候选区块的地形并集（matchBlocks 的 cellTypes 已是并集语义）：`{GRASS,WATER}` = 必发声、`{EMPTY,GRASS}` = 部分候选发声。输出"这条路线共 6 步，其中 4 步可能发声（2 步必发声）、1 步落在心跳窗口"。让玩家在"抄近路"与"潜行"间做知情选择。

**D12 危险区热图（防守视角）**  
`targets()` 已算出谁的捕捉目标是我。把猎手的位置候选集（各视角 locate / pair offsets）按其行动半径扩散，在地图上叠加红色危险区。行动顺序固定（0→N 循环）加持：**只有在我行动之前出手的猎手本回合能抓到我**，其余猎手的危险区推到下回合——`roundEnds` 数据已齐。

### 7.3 中成本层：需要新计算但结构清晰

**D3 一步风险图**：从当前位置枚举四方向：撞墙率（候选中墙占比）、树篱可冲率（上一步方向已知）、陷阱强停风险（候选含 TRAP 格且可能偶进）、门不确定性（状态 unknown 的门）。用饼状/色阶渲染在方向键上——"↑ 78% 通畅 / → 撞墙风险 40% / ↓ 可能陷阱（2 候选）"。

**D8 信息增益移动建议**：advice.js 的 probes 已经算出"记录某侧墙能把候选分成几组"——把它从"到达后该记哪"升级为"往哪走能获得最大分裂"：对邻格逐个评估期望候选收缩（信息熵减），排序输出。这是**探索阶段**的"该去哪"；D2 是**逃生阶段**的"该去哪"；两者共用 BFS 骨架。

**D11 截击点计算（猎手视角）**：目标候选位置集 ∪ 其下回合可达范围（BFS 扩散，含他可能穿墙/传送的不确定性保留），∩ 我的可达集 = 建议截击点。源码捕捉判定在**我的回合结束**时同格才生效（点杀默认开）——所以还要叠加行动顺序：目标若在我之前行动，需预判他**行动后**的位置（roundEnds + 他的典型移动模式）。工具已有全部输入。

**D9 计分器与策略权衡**：内置源码 Score 规则（逃生 150/200/250、抓人 ±100、金币 30、探索 1/2、退出 -300），实时显示"我现在逃生 vs 再探 10 格"的期望分差。当逃生舱数量少（残局）时提示"第 2 个逃生 200 分 > 环游世界的探索收益"这类具体权衡。

**D13 传送门捷径规划**：已验证传送门区块结构（2/6/13/14 对角门、15 同行、16/32 同列相邻）。区块一旦验证确定，传送门位置即已知——路径规划应把"进门 + 2 步亚空间 + 出门"折算为 3 步位移（spawnCheck 明确不用的捷径，决策模式里恰恰要用）。同时提示反转风险（单向门互换、ONEWAYPORTAL 只进不出）。

**D6/D10 隐匿与时机决策**：综合 D16（计划路线的暴露步数）+ D12（猎手距离）+ 剩余隐匿次数 → "这回合建议隐匿：路线含 3 个必发声格且 2 号（追你）候选位置距你 ≤4"。以及反过来提示对手隐匿（N11 落地后）：**对手候选集已被重置，别浪费方向约束去对他做近回合假设**。

### 7.4 远期：D14 局面推演 / D15 BOSS 危险度 / S9 复盘闭环

## 八、第四轮：头脑风暴（X 系列）

**前提**：A/B/N/S/D 系列全部落地——工具已经是"读得全、推得对、能建议"的决策助手。这一轮不再补短板，而是**找长板**：哪些能力能让它从"个人推理工具"变成"团队武器库/训练场/研究平台"。每项都先验证了可行性（含两项新的数学发现）。

### 8.1 两个新的数学发现（本轮最有价值的产出）

**X1（★）区块身份指纹定理——"区块雷达"的理论基础**  
对全部 71 区块实测：

- **纯墙模板**：61/71 唯一；仅 3 组重复：`5=S4`（水花大厅=黑洞）、`25=26=27=28=43=44`（六个"空墙+中心特殊格"的空旷系）、`31=E14`；
- **墙+地形类型**：仅剩 2 组：`25=26`（岩浆井 A/B 完全同构）、`27=28=43=44`；
- **墙+地形+附着**：**71/71 完全唯一，0 组重复**。

推论：**一个区块只要观测到足够多的墙边+一格地形行为，身份就是数学上确定的**。15 对 A/B 区块全是真差异（镜像布局不同），不存在"观测上永远不可分"的对。落到产品上：

- **区块雷达（实时识别侧栏）**：玩家每走过 3–4 格、看过几面墙，侧栏即时提示"你所在区块 87% 是 34 号忏悔室（还差左下格的墙确认）"。matchBlocks 的 cellTypes 已经在算这些，只差一个"从候选分布到人话"的渲染层与"还差哪格"的补全提示（advice probes 已有同款计算）。
- **格数下界提示**：对当前候选集计算"再观测哪一格的哪面墙能把组劈开"，就是 D8 在区块维度的特化——两者共享 probes 骨架。
- A/B 同构对（25=26 等）在游戏效果上等价，雷达应把它们合并显示为"岩浆井（A/B 等价）"，避免用户纠结无意义区分。

**X2 声响锥形三角测量**  
源码方向是 8 方位（斜向=直角锥形区域）。数学上：每个方向约束是两个半平面之交，**2–3 个相互远离的听者对同一声响的约束交集**通常只剩 1–3 格。工具的 relations 已存所有听者-声源对，pair 对齐后自动交叉——现在只用于对齐验证，**没有把"交集格"渲染到地图上**。落地：一声多报时在全局图画声源候选高亮，多声源时叠加。这是把已有数据"多卖一次"的纯渲染活。

### 8.2 团队协作层

**X3 合并导入（多人分工录入）**  
双人局各录各的视角、赛后（或局中通讯软件传 JSON）合并。journal 是纯消息数组，合并=重放并集；同回合同玩家出现不同轨迹时可复用现有 `skipReplay` 冲突检测逻辑报"两边记录矛盾"。导出/导入已有，缺的只是"合并模式"（现在导入是覆盖）。四/六人局里一人记公屏、各人记自己私信，合并后等于全信息——**这可能是把工具从单机变团队实战的第一杠杆**。

**X4 观战/解说模式**  
同一份合并存档，关掉"自己编号"绑定，全部视角平铺+时间轴（S7 已有骨架）：赛后团队复盘、当解说面板、或发社群"这局我们怎么推出来的"科普素材。

**X5 局中速记键**  
手机/平板用户加一排快捷按钮：四个方向键（记"我走了哪步"）、墙/空四键（记私信四墙）、沙沙/啪嗒键——点按直接生成对应消息文本进 journal。对局节奏快时，按键比粘贴整段更快更不易错。解析层零改动（生成的就是现有格式）。

### 8.3 表达与呈现层

**X6 均匀先验概率着色（可选皮肤）**  
README 正确地强调"候选不是概率"。但可以在**明确标注"假设均匀先验"**的前提下加一层可选热力皮肤：每格颜色深浅=候选中该地形/墙态的占比。开关默认关，打开时显著声明假设。对老手是快速读图增强，对新手也直观。

**X7 内置规则书与"易错点"知识库**  
rule.md + 两轮审查发现的全部语义细节（树篱冲刺、陷阱奇偶、心跳掩盖、首响保护、屏蔽器、门优先级、传送门初始化判定、出生回退、传送禁区……）做成可搜索的帮助面板，并**交叉链接到工具内的对应开关/着色**（"什么是候选一致推断？→ 看图例第 3 层"）。纯内容工作，但直接决定新用户上手成本。

**X8 候选地图对比滑块**  
局部候选列表里常有 5–20 张图，逐张点开很累。加一个滑块/左右键快速翻页 + 两图叠加差异高亮（不同的格子闪烁）。纯 UI。

### 8.4 训练与研究层

**X9 练习模式（本地出题）**  
71 区块数据 + engine 的 solveMap/verifyCompleteLayout 全在本地——完全可以**本地生成随机局面**（选池、随机 3×3 布局、模拟玩家游走、按源码格式生成"机器人消息"），让用户在无真实对局时练习推理，工具再用同一套推理引擎对答案（出题与解题共享 ground truth，天然自洽）。进阶：按题型出（纯墙推理/声响定位/传送门分支/门时序），错题记录。这也是给 D 系列决策功能积累训练数据的途径。

**X10 残局可判定性提示**  
剩 2 人时，追捕问题在图论上是**可判定的**：给定双方候选位置集与行动顺序，"我是否必然能在 K 回合内截击/他是否必然能逃到出口"是可达性问题（对每个候选布局分别判定再取交）。工具已有全部构件（witness 地图 + BFS + 行动顺序）。输出从"建议"升格为"定理"："在当前 3 个候选布局下，你都能在 2 回合内截到 2 号——除非他走传送门（那需要 3 回合）"。**决策建议里置信度最高的一档**。

**X11 决策回放审计（D 系列的闭环）**  
记录"工具每回合给了什么建议、玩家实际走了什么、事后看哪个更优"，赛后统计工具建议的采纳率与正确率。既是个人的"我该不该信它"仪表盘，也是功能迭代的实测数据来源。与 S9 复盘共用基础设施。

### 8.5 明确不做 / 降级的方向

- **OCR 截图识别**（拍公屏自动录入）：依赖外部服务或重型本地模型，与"无依赖本地工具"的定位冲突，且现有粘贴流程已够快。降级为远期可选。
- **对手风格建模**（对手爱走直线/绕墙的贝叶斯先验）：主观性强，与"候选不是概率"的严谨立场有张力；若做只能作为明确标注的启发式层，优先级最低。
- **实时联机协作**（WebSocket 多端同步）：X3 的文件级合并已覆盖 95% 场景，联机引入的复杂度（掉线/冲突/服务器）不成比例。不做。

## 九、结语（四轮合并）

四轮审查的结论层层递进：

1. **第一轮**：推理内核正确，问题在解析层——源码消息格式没接全（A 级四项）；
2. **第二轮**：还有 12 类信息源未接入，其中屏蔽器方位、金币拾取、门变化计数是"结构唯一、约束极强"的高价值信息（S1/S2/S4）；完整赛况+私信的拆分应由向导+完整性校验兜底（S5/S6）；
3. **第三轮**：假设以上全部落地，工具仍是"记录与推理面板"而非"决策助手"。从 D20（心跳安全窗口，零成本）到 D2/D4/D12（逃生规划/反向定位/危险区，数据已齐）再到 D14（局面推演），可以把工具推到"每回合告诉我怎么走"的形态；
4. **第四轮**：短板补齐后的长板方向——X1 区块雷达（本轮证明的 71/71 指纹唯一性）与 X3 合并导入把工具推向团队实战；X9 练习模式与 X11 决策审计让它自我进化；X10 残局判定给出置信度最高的一档建议。

一个贯穿四轮的实施原则：**每加一类输入，先固化真实消息样本为回归测试；每加一个决策功能，先在 UI 上展示它的依据（哪条约束、哪个 witness），让玩家能核查而非盲信。** 决策建议永远标注置信来源（观测事实 / 候选推断 / 唯一验证 / 数学判定），与地图着色体系保持一致——辅助工具的信誉来自"说清楚自己什么时候会错"。

### 对若干建议前提的修正

- S1：屏蔽器与小太阳是可推动箱子，不能把初始区块中心当作始终固定的位置；热浪也可能来自热源。

- D4 / D17：对手模型仅包含本工具掌握的公屏和可用约束，不能代表对手实际收到的私聊或完整知识。反向提示不等于已知对手知道什么。
- S2 / S4：金币可能来自抢夺；门公告是回合总量。必须匹配事件时序与完整性，不能将总量随意归给单一步或单个按钮。
- X1 / X6：模板指纹唯一不保证有限且含动态变化的观测唯一。未建立采样权重前，不把候选占比说成真实概率，A/B 编号也不能因局部外观相同而合并掉唯一性约束。
