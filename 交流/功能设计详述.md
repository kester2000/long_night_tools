## 输入区 · 双模式（TODO P0-1）

**场景**：对局在手机 QQ 群；电脑只有本地网页，与手机无任何通道。有条件复制原文时粘贴最高效；对局中只能瞄一眼手机，靠按键"打"消息。

**结构**：输入区显式两模式，一键切换、选择记忆到 localStorage：

```
┌────────────────────────────────────────────┐
│ [ 📋 粘贴模式（默认） ]  [ ⌨ 手动模式 ]      │
├────────────────────────────────────────────┤
│  粘贴模式：现有大输入框（不变）                │
│  手动模式：速记面板替代输入框主区域             │
└────────────────────────────────────────────┘
```

### 模式一：完全粘贴模式（默认，零风险基线）

- 现有大输入框原样保留：整段原文 → 现有解析 → S6 输入预览 → 提交。不动任何现有行为。
- 可选增强：
  - **智能切分**：粘贴大段时按 `【第 N 回合】`/`[N号]` 边界自动切成多条消息预览，逐条确认归属后批量提交（复用 S6 闸门）；
  - **常用片段按钮**：`开局墙` `当前回合墙` `完整赛况头` 骨架一键插入，只需补数字。

### 模式二：纯手动输入模式（速记面板）

核心原则：**传意图不传文本**——按键组装标准格式消息，生成后先进同一输入预览闸门再提交。所有生成文本已实测通过现有 parse、靠消息 `view` 机制自动归属，**解析层零改动**。

- **状态行**：`第 N 回合 · 当前录入 X 号 · 本回合已录 Y 条`；`Tab` 按行动顺序推进到下一人；可点任意玩家跳录。
- **轨迹速记**（最高频）：
  - `↑↓←→` 按钮 + 键盘方向键/WASD 加步；路线实时显示为缩写串（`→×3[↓啪](←撞)`）；
  - 步修饰：`1`沙沙 `2`啪嗒 `X`撞墙 `M`×N；连续同向自动累积 ×N；
  - 结束标记：陷阱/逃生/捕捉/传送/热源/浆果/停止（生成对应 marker）；
  - `Enter` 生成预览、`Ctrl+Enter` 直接提交。生成物形如：
    `[1号]玩家本回合的完整行动轨迹：\n【第 N 回合】\n→×3[↓啪嗒](←撞)`
- **墙壁速记**：2×4 三态格（上下左右 × 墙/空/?，点击循环）→ 自动带当前回合号与视角 → 生成 `【第 N 回合】\n您所在位置的四周墙壁信息…\n墙空空墙`。开局墙独立按钮。（实测：文本无需玩家编号，view 归属正确进 pending。）
- **声响速记**：九宫格方位盘（八向+同格）+ 沙沙/啪嗒/被屏蔽/首次 → 步数自动+1 可改 → 生成 `[1号(第2步)]你听见了来自【正上方】的沙沙声！`；同格/被屏蔽生成 A3 修复后的对应原文。
- **速记缓冲**：同回合多条（轨迹+墙+声响）先积一屏，核对后批量提交；单条退格、整屏可弃。
- **键盘总表**（印在面板底部）：`0-7`切玩家 / 方向键加步 / `1/2`声响 / `X`撞 / `M`合并 / `Tab`下一人 / `Enter`生成 / `Ctrl+Enter`提交 / `Esc`清空 / `P`切回粘贴模式。

**互操作**：生成文本与粘贴走同一预览闸门（可见将提交什么、归属谁）；粘贴模式随时切手动补一条，手动模式一键切回贴大段；手动消息在列表带 `⌨` 标记，赛后核对"凭眼录入"的潜在错录点。

**成本**：纯 UI（开关+面板+拼装函数+view 设置+缓冲区）；5 类生成格式已实测通过 parse；对局中从"手打 100 字/条"降到"约 10 次按键/条"。

## V2 冲突向导（TODO P0-2）

**实测缺口**：开局贴"墙墙墙墙"再贴"↑×9 成功移动"→ 候选**静默清零、零警告**。用户不知道哪两条观测打架、该撤销哪条。录错（抄错方向/归属错视角）在对局中几乎必然发生。

**设计**：候选清零/大幅收缩时自动**逐条移除观测重算**（二分定位），找出"拿掉哪条后候选恢复"，输出人话："第 3 条消息的『墙空空墙』与第 7 条的『↑↑ 成功移动』矛盾（开局处上方是墙，不可能向上走）。可撤销：[第 3 条] [第 7 条]。"按钮直接打开对应消息编辑框。

**成本**：引擎层是现有 matchBlocks 循环调用；观测多时可先按消息分组二分再细到条。

## V1 录入价值反馈（TODO P0-3）

每次提交后在消息卡片显示候选**前后对比**："全局候选 16 → 9（−7）；1 号区块候选 5 → 2"。现状只有绝对数（candidate-count），没有"这条消息值多少信息"。

价值：①"贴了没用"当场可见（大概率归属错了）；② 与手动模式 ⌨ 标记配合，错录即时暴露而非事后地图崩。实现：提交前后各取一次计数，纯 UI。

# 搁置与排除（不进 TODO，留档备查）

## 搁置（条件成熟可启用）

- **Z1 手机直投页**（局域网可用时）：server 监听 `0.0.0.0`（或 `--lan`）+ `GET /inbox` 手机极简投递页（textarea+视角选择）+ `POST /inbox` 队列（内存+`inbox.jsonl` 落盘）；电脑主页轮询 pending **只预填不自动发**（保留 S6 闸门）；可选 6 位口令；手机同 Wi-Fi 访问 `http://<电脑IP>:4173/inbox`；Windows"移动热点"兜底无路由器；落盘复用 `journal=next; save(); rebuild()` 三步。配套：投递页预选视角、待收队列 UI（角标/采纳/丢弃）、断线补收。**当前搁置原因：用户环境电脑与手机无通道。**
- **Y5 多局档案柜 / Y6 对局统计 / Y8 浅色主题 / Y10 剪贴板监听 / Y11 对手视角查看 / Y13 声响回溯表**：2026-10-15 按用户"不要无关紧要的"指示移出主动计划；如有明确需求再议。
- **X4 观战模式 / X5 速记键**：已按用户界面精简要求移除；界面需求变化再议。
- **X2 声响锥形交叉高亮**：数据在 relations，纯渲染；随 S7 证据矩阵一起做更划算。

## 排除（明确不做，附理由）

- **语音输入**：大段文本场景覆盖约 5% 输入量，收益/成本比过低。
- **PWA/manifest**：本地 server 已满足离线；Z1 投递页（若启用）比"添加到主屏"更直接。
- **地图手绘画笔**：与笔记功能重叠，且有"手画被当成事实"的混淆风险。
- **Z2 二维码传大文本**：容量撑不起整段赛况，只够设置类短消息。
- **Z3 NTQQ/NapCat 机器人转发**：第三方协议实现，封号风险+配置复杂，不作为默认路径（工具保持零依赖）。
- **云中转/公网服务**（网盘/在线剪贴板/公网隧道）：数据出局域网、引入账号与可用性依赖，与"本地保存 · 无需联网"定位冲突。
- **QQ"我的电脑"传文本**：需电脑装 QQ，不符合"电脑只有网页"场景。
- **对手风格统计/胜率预测**：样本小、主观性强，与"候选不是概率"立场冲突。
- **自动 OCR 截图**：依赖外部服务或重型本地模型，与零依赖本地工具定位冲突（前几轮已多次确认）。
- **实时联机协作（WebSocket 多端同步）**：文件级合并（X3）已覆盖 95% 场景，联机复杂度不成比例。
